### 2026-09-23 — Qualifier search: experimental build confirms the design, and finds four defects

- [2026-09-23] `07-investigations/030-palette-qualifier-search.md` — **added section 10**, recording what an experimental build proved. Branch `experiment/palette-qualifier-chips` off `upstream/master` @ `f4d37904a6` implements a vertical slice (parse `qualifier:value` → compile via `->dsl` → run via `frontend.db.query-dsl/query` → render a `:query` palette group), with 8 unit tests / 28 assertions. **Confirmed live in Chrome** on graph `demolocal4`: `tag:Task` → `(tags [[Task]])` → 14 results rendering above Nodes; `tag:Task tag:Card` → `(tags [[Task]] [[Card]])`, multi-value OR working; `tag:Task -task:Done` → negation compiling; `-tag:Task` → no query run, the positive-clause guard holding; `Chapter 3: Notes` and `foo:bar` → no Query group, colons and unknown qualifiers left as free text. The assumption everything rested on — that the palette can execute a DSL query and render its results — is answered yes.
- [2026-09-23] `07-investigations/030-palette-qualifier-search.md` — **three corrections to the design**, each found by building it. (1) `->dsl` could **not** emit a multi-value form: a branch in `->dsl*` shadowed the general one and read only `(second f)`, so `[:tags "project" "infra"]` silently became `(tags [[project]])` — the repeated-qualifier OR the operator model rests on. Unreachable before because the query builder only emits single-value tags. The two-stage-pipeline claim survives; "reuse `->dsl` unchanged" does not. (2) `execute-query` returns **tuples**, `[[block] [block] …]`, so consuming it as a seq of blocks silently yields nothing. (3) **`(task …)` returns 0 against data that matches** — added as a fourth row to the defects table and the only one **reproduced live**, through the plugin API with no experiment code on the path: `(tags [[Task]])` → 14 but `(task Done)` → 0, while raw Datalog finds three Done tasks. Ruled out: statuses present on all 14 nodes, `:logseq.property/status` is `public? true`, the closed value carries `:block/title "Done"`, quoting is irrelevant (`build-task` applies `(comp capitalize-all name)`), and the rule chain plus `rules-dependencies` map are complete. `priority` shares the rule and is likely affected; of the stage-1 vocabulary only `tags` is confirmed against real data.
